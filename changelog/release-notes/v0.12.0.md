# v0.12.0 — project-pack service knowledge, global-skill safety, ui overhaul

Package: `xtrm-tools@0.12.0` · Extensions: `@jaggerxtrm/pi-extensions@0.12.0`

> Coordinated release counterpart to `Specialists 3.21.6` (`@jaggerxtrm/specialists@3.21.6`, tag `v3.21.6`). Install with matching versions for project-pack resolution parity.

## Summary

0.12.0 delivers the Core side of the 3.21.6 service-knowledge project-pack contract, closes a destructive global-cleanup path with verified archive rollback, retires five pi-extensions cleanly, moves session naming under the launcher, and lands a full xtrm-ui rendering overhaul. No API break; docs and README now reflect the 0.11.6 surface.

## Project-pack service-knowledge resolution + Claude loadability (PR #609 · ef14bf44 · xtrm-lk07w.14)

Resolves bare skill names declared in v2 project packs (`.xtrm/skills/<pack>/`) with runtime-targeted views (`SEC-07`). Tie-in to Specialists 3.21.6 service-knowledge project-pack binding: `xt pi --role` and `xt claude --role` share the same canonical identity, slot-dir, and fail-closed probe semantics — bare names, direct paths, global fallback, and shadowing checks are deterministic. Claude preflight gates the combined role plus explicit set for native discoverability and pack divergence before linking; materialization is transactional with worktree and launcher-branch rollback on failure. Pi retains native `--skill`; Codex fails closed on project-pack resolution for every role launch including `--bead`. Built `cli/dist` parity re-verified after rebuild.

## Destructive global-cleanup prevention (PR #608 · b8697569 + 28aed2d9 · xtrm-qs9in)

Global skill pruning now requires prior ownership before removing retired default skills, backs up and atomically restores the complete global skill tree on bootstrap failure, and preflights global prompt sync before mutating. Verified archive rollback was exercised and is covered by a seeded retirement ownership proof (`test(skills): seed retirement ownership proof`). Prevents data loss on update when global state was never owned by the installer.

## Retire 5 pi-extensions cleanly + dist rebuild (PR #607 · aead627f + 5d7d3a43 · xtrm-lqfjq)

Removes five retired extensions cleanly and rebuilds `cli/dist` after the registry fix. No behavioral change beyond the reduced extension set; distribution bundle reflects the trimmed registry.

## Launcher-owned --name from worktree slug (7f5874c1 · xtrm-rhmm1)

`xt pi` / `xt claude` --role now derives `--name` from the worktree slug on the launcher side and drops the extension auto-session-name. Single source of naming, no collision with the launcher's tmux session identity.

## xtrm-ui overhaul

- **Single-line statusline (PR #598 · 1e6c2f5 + 0850349c)** — Pi footer and Claude hook render as one line; parity test updated to the single-line contract.
- **Native-style external tool rows + model accent (PR #599 · 1fd58895)** — External tool rows match native shape (extension name in `#9a8bff` bold, tool name bold dimmed until success) with the model accent for readability.
- **External tool-frame patch retry (PR #600 · 18bc72f6)** — Retry installing the external frame patch on `session_start` so late-registered external tools are themed correctly.
- **Prototype patch replacement without stacking (PR #601 · 5312a04)** — Replace Pi prototype patches without wrapper stacking on reload, removing the reload hazard that accumulated wrappers.
- **Bundled Pi runtime class patch (PR #604 · 296be42)** — Patch the active bundled Pi runtime classes so theming applies to the runtime actually in use, not a stale path.
